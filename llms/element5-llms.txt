# Element5

> Element5 is a post-acute healthcare workflow automation platform. Its Neos AI agents automate revenue cycle management (RCM) and back-office operations — eligibility and benefit verification, prior authorization, claims processing, denials management, remittance/collections, and audit/compliance — for home health, hospice, and palliative care providers. The public Element5 API (v2.2.0) is API-key protected and lets clients submit authorization and eligibility requests, process X12 270/271 eligibility transactions, exchange files via an object store, and monitor long-running tasks by polling or via webhook callbacks.

## APIs

- [Element5 API documentation](https://api-doc.e5.ai/): API-key (X-API-Key header) protected workflow API; base URL https://api.e5.ai (non-prod https://api-qa.e5.ai).
- [Element5 OpenAPI 3.1.0](https://raw.githubusercontent.com/api-evangelist/element5/refs/heads/main/openapi/element5-openapi-original.json): 8 operations across Automation, Object Store, Authorization, and Eligibility.

## Operations

- submitAuthorizationRequest — POST /wf/v2/workflows/submit-authorization
- getSubmitAuthorizationRequestStatus — GET /wf/v2/workflows/submit-authorization/{task-id}
- submitEligibilityRequest — POST /wf/v2/workflows/submit-eligibility
- getSubmitEligibilityRequestStatus — GET /wf/v2/workflows/submit-eligibility/{task-id}
- processX12EligibilityTransactionRequest — POST /wf/v2/workflows/process-x12-eligibility-transaction
- getProcessX12EligibilityTransactionRequestStatus — GET /wf/v2/workflows/process-x12-eligibility-transaction/{task-id}
- uploadFileObject — PUT /store/v1/file-object
- getFileObject — GET /store/v1/file-object/{object-id}

## Events (webhooks)

- E5TaskEvents callback: task#queued, task#started, task#restarted, task#progressed, task#succeeded, task#failed
